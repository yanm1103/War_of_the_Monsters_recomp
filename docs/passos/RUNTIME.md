## Fast build (no LTCG)
The PS2Recomp release turns on `/GL` + `/LTCG` and the link takes ~28 min on every change. With `-DPS2X_FAST_LINK=ON` (branch `wotm`) the game still runs at 60 fps; incremental rebuild in ~13 s, from scratch in ~4 min.
- **Always use `build_runtime.bat`** at the repo root (or `tools/build_runtime.ps1`): it configures `build_dev` with `-DPS2X_FAST_LINK=ON -DPS2X_ENABLE_AGRESSIVE_LOGS=OFF -DPS2X_ENABLE_IOP_RPC_TRACE=OFF`, touches `ps2_runtime.cpp` (ninja does not track `native/`), generates the native VU0 `.inc` when it is missing and compiles. **Two executables** come out in `build_dev\ps2xRuntime\`, from the same objects of the translated game: `wotm.exe` (the game, without emulated GS/VU1/VIF1 and without the check) and `ps2EntryRunner.exe` (test: emulated, `WOTM_VU1CHECK`, `WOTM_FOTOS`, `--vu1cmp`; the one `corpus.ps1` and `vu1cmp.ps1` use). The clone's `build_dev.bat` compiles both (`--target ps2EntryRunner wotm`). Details in `FRONTEIRA.md`, step 5. `build_runtime.bat nm` does the same for the test-subject runtime (`build_dev_nm`).
- **Aggressive logs have to stay OFF.** `PS2X_ENABLE_AGRESSIVE_LOGS` comes `ON` upstream: every generated function writes entry/exit with flush (295 MB in 45 s) and the boot does not get past Press Start.
- **Instruction helpers always inline:** the register, memory and FPU helpers that the translated code calls on every instruction (`Ps2SetGprLow64`, `Ps2ExtractEpi64`, `Ps2FastRead*`/`Ps2FastWrite*`, `ps2_fpu_fix`, `Ps2IsSpecialAddress`...) are `__forceinline` (`PS2_FORCEINLINE` in `ps2_runtime_macros.h`, `PS2_ADDR_FORCEINLINE` in `ps2_address.h`): in the translated functions, which are huge, MSVC gives up on ordinary inlining and each one would become a call. The rare path (an access that wraps around the end of RAM) stays out of line. `READ*`/`WRITE*` have a shortcut to the scratchpad (16 KB at 0x70000000 and at the mirror 0xF0000000; aligned access only), straight into the buffer, without the runtime's `Load`/`Store`; the 32-bit write still services completed DMAs, like `Store32`, through an atomic flag (`PS2Memory::hasCompletedDmacCauses`) instead of the mutex. Changing these headers recompiles the game's 169 units (~12 min).
- The build links with `/MAP` and `/DEBUG` (PDB with public symbols only, without `/Zi`; `/OPT:REF /OPT:ICF` keep the binary; `cmake/ReleaseMode.cmake`, `PS2X_FAST_LINK`). `PS2X_HOSTPROF` resolves names through the PDB. On a crash, `crashFilter` writes the `[CRASH] exe+0x…` and then the stack of the thread that crashed, each frame with its name from the PDB next to the exe (`wotmCrashTrace`, `wotm_standalone.cpp`; `WOTM_CRASHTEST=1` triggers one). Public symbols only: a `static` function shows up with the name of the previous public one and a large offset. Without the PDB, look for the largest symbol ≤ the address in `wotm.map`.
- **Release package:** `powershell -ExecutionPolicy Bypass -File tools\release.ps1` assembles `<runtime>\release\WotM-<versão>-win64.zip` and the `.sha256`, outside the repo (the exe has the game's translated code; the zip goes only to GitHub Releases). It takes the `wotm.exe` from `build_dev` (no LTCG: it does not change the fps, and the exe in the zip is the same one tested) and `wotm.pdb`, the DLLs the exe pulls in (closure via `dumpbin`: FFmpeg and dependencies from the build folder; `MSVCP140`, `VCRUNTIME140` and `VCRUNTIME140_1` from the Visual Studio redist, without `/MT`), the files of `mods/` that git tracks plus `MECHA.NGP/PTR/TEX/RTX` (generated by `tools/mechamon.py`, in `.gitignore`; owner's decision: ready-made in the zip), and `tools/release/` (the player's `README.txt`, `THIRD_PARTY.txt`, `licenses\`, plus the repo's GPL and the PS2Recomp, raylib and GLFW licenses taken from the build). It refuses: an exe of a version other than the current `git describe`, a repo with local changes (`-AllowDirty` for testing), a console exe, a DLL not in `THIRD_PARTY.txt`, and any file from the disc or from the packager's PC (`SCUS_*`, game formats, `save.json`, `settings.ini`, logs) other than the `MECHA.*`. Names in the zip use `/`.
- **Version:** `build_runtime.ps1` writes the repo's `git describe --tags --always --dirty` to `<build>\wotm_gen\wotm_version.gen.h` (`WOTM_VERSION`, `native/wotm_version.hpp`; `dev` without git). It shows up on the first line of the log (`[wotm] War of the Monsters Recompiled <versão>`) and in the window title. A release is a tag in the repo.

## Running
- `run_live.bat` (or `run_live.ps1` in the clone: `-Auto 0` to play, `-Stats 1` logs `[native]`, `-Build build_dev_nm` for the test subject, `-Exe test` forces the test one). It runs `wotm.exe`, except with `WOTM_VU1CHECK` or `WOTM_FOTOS` on (`run_live.bat` turns photos on by default; the launcher does not), with `-Exe test` or when `wotm.exe` is missing or older: then `ps2EntryRunner.exe`. It sets `PS2X_NO_VU1=1 PS2X_NO_VIF1=1 PS2X_NO_GS=1 PS2X_SCENE=1 PS2X_FMV=1` (emulated VU1 and GS off in the test one, native drawing and movies; `wotm.exe` turns on the cuts, the drawing and the movies by itself). It uses `Start-Process -RedirectStandardError` on purpose (PowerShell 5's `2>` writes UTF-16). Logs in `<runtime>\logs\` (`live.err.log`/`live.out.log`; the build writes `build_dev.log` there and `live_attack.ps1`, `atk.*.log`); the runtime root holds only scripts and folders.
- **`wotm.exe` with no argument** (double-click, the release zip; `native/runtime/wotm_standalone.cpp`, called by `main.cpp`): the exe plays the role of `run_live` by itself. Data folder = the exe's folder, if it is writable; otherwise `%LOCALAPPDATA%\WotM` (Local, not Roaming: `wotm.ini` stores a path on this machine). It holds `SCUS_971.97`, `wotm.ini` (`iso=<caminho da ISO>`, UTF-8; `PS2X_CD_IMAGE` wins), the cwd, and, since they follow the ELF's folder, `mc0\`, `save.json`, `settings.ini` and `screenshots\`. **First run** (no ELF, or the ISO is gone from the saved path): a box explains and opens the Windows file picker; `SCUS_971.97` comes out of the ISO9660 root, the SHA1 has to be the NTSC-U one (`1ed7f845…`), and then the ELF and `iso=` are saved; a file that is not a game ISO or a different SHA1 gives the message and the picker again; cancel closes the game. Mods: `<dados>\mods`, otherwise `mods\` next to the exe. Log: stderr to `wotm.log` and stdout to `wotm.out.log` (the previous ones become `*.prev.log`), only when stderr is neither a file nor a pipe. With an argument (`run_live`, batch), none of this runs. `wotm.exe` is always a window app (`/SUBSYSTEM:WINDOWS`, no console; `PS2X_SHOW_WINDOWS_CONSOLE` only applies to `ps2EntryRunner`) and turns on `PS2X_SCENE` in both cases.
- Direct match without the menu: `WOTM_MATCH=<jogador>[,<ia>...],<fase>` (0 to 7 AIs; no AI = alone in the stage); AI vs AI: `WOTM_AIVSAI=1`; batch: `tools\lote.ps1` (all in `NATIVO.md`).
- Other useful `PS2X_*`: `PS2X_PAD` (button script with timings), `PS2X_DUMP_RAM="3300,3900"` (writes `ram_<q>.bin`/`vram_<q>.bin` for the viewer), `PS2X_CD_IMAGE` (ISO), `PS2X_PEEK="hex,hex"` (RDRAM words in the log), `PS2X_HOSTPROF_RAW=1` (with `PS2X_HOSTPROF`: each sample of the EE thread becomes a line `rip w1 w2 ...` in `hostprof_raw.txt`, addresses relative to the exe, to resolve with `wotm.map`, which also has the static functions; those outside the exe come out with their names in `#sym` lines; `PS2X_HOSTPROF_SKIP=<s>` discards the first seconds), `PS2X_VU0PROF=1` (in `wotm.exe`, time and calls per VU0 microprogram on the `[time] vu0` line of `PS2X_STATS`; in `ps2EntryRunner.exe` always), `PS2X_HOSTPROF=1` (host RIP sampler, all threads every ~1 ms, `hostprof.txt`; `=2` only the EE thread, or the window's with `PS2X_HOSTPROF_WIN=1`; `=3` only the EE thread and only when its frame goes over 100 ms, waking every 50 ms; with `WOTM_FIELDLOG`, a frame over 100 ms comes out as `[hostprof]` with the approximate call chain), `PS2X_COVERAGE` (function coverage), `PS2X_IOP_BATCH` (default 256).
- **Keyboard** (backend in `ps2_pad.cpp`, adds to the gamepad; default map, changeable in the CONTROLS tab of "Recompiled options", `NATIVO.md`, "Key and button rebinding"): **arrows = left analog**, **I/J/K/L = D-pad**, **Space = X**, **Z = square**, **X = triangle**, **S = circle**, **Enter = Start**, **Backspace = Select**, **Q = L1**, **W = R1**, **Shift = L1+R1**, **A = L2**, **C = R2**. Native layer: **F3** FPS, **F7** pauses and resumes, **F6** (paused) advances one game frame, **F8** takes a photo with a note (with `WOTM_FOTOS`; with `WOTM_VU1CHECK` only, records and compares the next frame). Flow in `VU1CHECK.md`, "Photos".

## Boot trace (black screen before the movie)
From process start to the first movie, the runtime writes each stage to stderr with the time since the start and shows the stage on the black screen ("Loading... 3.2 s"). Always on; stops when the boot ends. A stage stuck for more than 2 s repeats as `... ainda em "<etapa>" ha N s (PC do EE 0x..., vsync N, R/s)`: map the PC with `config/status.csv`. Measured: window 0.6 s; IOP modules 0.8 s; then the game sits idle ~3.5 s counting vsync at 60/s (the game's own wait, it grows if vsync drops); movie at 4.4 s. Code: `wotmBoot*` in `wotm_live.inc`.

## Useful addresses (menu)
`currScreen` 0x6F8464 (0x14 = Press Start, 1 = menu and also inside the stage, 0x63 = loading), `nextScreen` 0x6F846C, `betweenScreens` 0x6F7E8C, `screenFirstPass` 0x6F7E80, `targetAlpha` 0x6F7E74, `fadingIn/Out` 0x6F807C/0x6F8080, `world` 0x6F87C4, `g_frame` 0x6F7E38. In new code use `wotm::sym::<nome>` (`native/wotm_syms.h`).
