# Linux port progress

## Scope

Native Linux x86-64 development build and launch, keeping the Windows build intact. This log tracks implementation and verification; it does not claim Linux support until gameplay has been tested on Linux.

## Status

| Milestone | Status | Evidence / blocker |
|---|---|---|
| Baseline and requirements | Complete | GCC 14.2, CMake, Ninja, and FFmpeg development libraries are available. The ISO in `Game/` passed the retail ELF SHA1 check; generated files remain ignored/local. |
| Native source portability | Compiles | The Linux runtime built successfully, including the recompiled game and native layer. GCC 14 still warns about existing `std::filesystem::u8path` calls and `-Wfree-nonheap-object` in the ISO9660 parser; the actual NTSC-U image passed standalone SHA1 validation. |
| Linux setup/build/run scripts | Smoke-tested | Setup and build completed; launch works repeatedly and now discovers ISOs in `Game/` as well as `ISO/`. The standalone first-run path has Linux GUI/terminal ISO selection and XDG data-directory fallback. |
| Linux menu boot | Verified | The menu and monster-selection UI rendered with native fonts/prompts and stage resources. |
| Linux gameplay verification | Partially verified | The first-run GUI ISO picker validated the retail image, then the game booted to the menu with bundled assets. Keyboard navigation entered Adventure and loaded a fight; a 3-player AI match completed a round, and a 4-player AI fight ran without a crash. The DragonRise pad was enumerated as player 1; synthetic `uinput` events through a matching DragonRise gamepad navigated the in-game pause menu, but physical button/axis behavior remains unverified. Both boot FMVs rendered, and a PulseAudio monitor capture contained non-silent stereo output. An Adventure stage was saved through the game UI, then loaded after relaunch from the same XDG data directory and resumed at the next stage. X11 fullscreen is verified on i3; full campaign progression, physical controller behavior, Windows regression, and non-X11 window managers remain untested. |
| X11 fullscreen | Verified on i3 | Default borderless mode requests EWMH fullscreen on the selected monitor without changing the XRandR mode; first-run and repeated F11 toggles were verified on eDP-1 at 1920×1080. |
| Packaging | Built and validated; not publication-ready | The AppImage is built on Ubuntu 22.04 x86-64 and passes the GLIBC 2.35 ABI ceiling checks. On Jammy, the no-helper graphical first run accepted the user's ISO, verified the retail ELF SHA1, extracted it to XDG data, and booted to Press Start. On Void Linux/X11, the final artifact mounted with FUSE and booted to Press Start on eDP-1; `LD_DEBUG` confirmed Mesa used the host C++ runtime. The package excludes the ISO, retail ELF, disc files, and mods. Corresponding-source obligations, Wayland/XWayland, and broader distribution testing remain unresolved.

## Baseline findings

- `third_party/PS2Recomp` is a modified submodule checkout with local edits. Do not reset, overwrite, or regenerate its files as part of this work.
- `third_party/ps2-recomp-Agent-SKILL/` is untracked user data. Preserve it.
- The previous Linux experiment is available in Git history as `7df1f85:docs/investigacoes/2026-10-30/linux.md`; it reached the menu but did not test a fight and used placeholder behavior for some embedded resources.
- Linux prerequisites present: GCC 14.2, CMake, Ninja, pkg-config, Python 3, and FFmpeg development libraries.
- `Game/War of the Monsters (USA).iso` is local input. Its extracted ELF SHA1 is `1ed7f8457436a9170d8f85386e267369c7fcdd4f`.
- Extracted disc, translated game code, PS2Recomp checkout, and runtime build are ignored/local. Do not add them to Git.

- 2026-11-04: Fixed the launch script's repeat-run handling (an existing per-user ELF had made `cp -n` abort) and added automatic ISO discovery under `Game/`. Verified menu/selection and a direct AI-vs-AI fight using X11 screenshots; confirmed the fight window was on `eDP-1` (root position x=2880 while eDP-1 spans x=1920..3840). Restored HDMI-1 as the desktop primary after testing. Gameplay remained live without a crash during the smoke test.
- 2026-11-04: Added Linux standalone behavior for read-only installs (XDG/HOME data path), ISO selection via Zenity/KDialog or terminal, and log files for interactive launches. Verified the XDG fallback and terminal-based first-run path with the retail ISO; extracted ELF SHA1 matched.
- 2026-11-04: Verified the Zenity first-run picker with a clean temporary install: it selected the ISO in `Game/`, checked the retail ELF SHA1, extracted the ELF, and booted the game with the bundled font and prompt atlas. Keyboard input navigated the menus into Adventure and loaded the first fight on `eDP-1`; the native audio device opened. This does not yet establish sustained combat, audible output, controller support, save/reload, or Windows parity.
- 2026-11-04: Changed setup extraction to use a fresh temporary directory before accepting the retail ELF. A stubbed extraction test confirmed that an existing `disc/SCUS_971.97` cannot make an ISO with no ELF pass validation.
- 2026-11-04: Verified both boot FMVs on Linux; `intro_m.pss` completed and `int_main.pss` rendered, then skipped on input. The app opened a 48 kHz stereo stream, and a PulseAudio monitor capture contained non-zero audio. Saved Options through the game UI, relaunched with the same XDG data directory, and confirmed the save JSON was read. The DragonRise controller was recognized as player 1; a matching synthetic `uinput` pad moved the in-game menu selection, but physical controls were not actuated. Sustained 4-player AI combat ran without a crash. Its measured 4-view redraws varied from about 15 to 21 ms, so 60 Hz is not consistent in that mode; the short profile did not isolate a safe code-level optimization, so no rendering changes were made. Campaign save/continue, full physical controller behavior, and Windows regression remain open.
- 2026-11-04: Used `WOTM_CHEATS=inv,vencer=5` to finish one real Adventure stage, saved slot 1 via the game's Save Game flow, closed the runtime, and relaunched from the same XDG data directory. The save list showed Togera at Gamblers Gulch with the score, lives, and stage progress; loading it logged `aventura do slot 1 carregada` and resumed gameplay in Vegas. This verifies one save/continue cycle, not a full campaign playthrough.
- 2026-11-04: Fixed the Linux borderless fullscreen path for X11 window managers: it now sends EWMH fullscreen add/remove requests while retaining the current display mode. On i3, verified the default first-run mode, repeated F11 enter/exit, and live UI transitions between borderless and exclusive modes at eDP-1 (1920×1080, `_NET_WM_STATE_FULLSCREEN`, i3 `fullscreen_mode=1`), with XRandR mode/refresh unchanged. Rebuilt `wotm` and `ps2EntryRunner`, confirmed the runtime patch applies to the pinned base, and replayed a Linux VU1 corpus of 10 menu/fight/debris frames against its pre-change baseline with no summary differences. This corpus is Linux-only and does not replace Windows regression.
- 2026-11-04: Built the AppImage from an Ubuntu 24.04 x86-64 rootfs with pinned LGPL-only FFmpeg 7.1 and a pinned AppImage runtime. Verified the payload/checksums, then ran it on Void Linux in extraction mode using a fresh XDG data directory; the first-run Zenity picker accepted the user's ISO, the extracted ELF SHA1 matched retail, `intro_m.pss` completed, and gameplay rendered on eDP-1. This validates one cross-distribution X11 run only. Corresponding-source obligations remain unresolved, so the AppImage is not ready for public release.
- 2026-11-05: Rebuilt the AppImage on Ubuntu 22.04 with a GLIBC 2.35 ceiling and statically linked, hidden GCC C++ runtime symbols. This avoids putting Jammy's `libstdc++` on the process-wide library path, which had broken host Mesa/Z3 on the newer Void system. The final AppImage passed payload and checksum checks; its `wotm` ELF has no dynamic `libstdc++`/`libgcc_s` dependency or GLIBCXX/CXXABI version needs. A clean no-helper first run on Jammy accepted the ISO with spaces, pasted a UTF-8-suffixed path and removed its final code point with Backspace, matched retail ELF SHA1, extracted into XDG data, and reached Press Start on eDP-1. The final artifact also mounted with FUSE on Void/X11, reached Press Start on eDP-1, and `LD_DEBUG` showed Mesa resolving C++ symbols against the host runtime. `tools/test_check_appimage.py` passes 16 tests. Corresponding-source obligations remain unresolved; Wayland/XWayland, full campaign progression, physical controller behavior, Windows regression, and non-X11 window managers remain unverified.
