# Mod ideas

- **GTA SA pedestrians and a playable full-size CJ:** today's pedestrians are particles (fx 91–99, `VU1CHECK.md`), so 3D NPCs are new drawing and animation.

- **Nintendo DS mode:** LOD always at the lowest level (the LOD is chosen by the native layer); real-time audio filter in the native sound (`wotm_snd.hpp`); maybe two screens, the game on top and the HUD below with the portrait (the `hier` HUD is already drawn by the native layer).
  - **Where the LOD is chosen:** in the native drawer, `Scene::walk`, case 2 (`native/wotm_native.hpp`). It redoes the game's rule (the LOD case of `hierTraverseAsm`, `0x207820`): distance² from the node center (`+0x10`) to the view's eye, highest index with `d² < switchOutDis`; none, the node does not draw (this is also the distance culling). Cross-fade with the level's `fade` (`DrawItem::fade`, `lodX`). The game does not store the choice and none of the logic depends on it, so changing the rule only changes the drawing. Changing `hierLod` (dead code, nobody calls it), `hierTraverseAsm` (a PS2Recomp seam, it only changes the VU1 packets) or the `switchOutDis` in RAM (it contaminates snapshots and replay) does not work.
  - **LOD node** (`include/hieri_types.h`, `docs/FORMATOS.md`): `numLods` at `+4`, `lods[i]` at `+0x20`, 16 bytes each (`fade`, `switchOutDis` in distance², `child`). Index 0 is the coarsest.
  - **What has LOD:** monsters (`CS` → `CHAR_INSTANCE` → `SKEL_BONE` + `LOD`; up to 4 levels, the skeleton is the same for all), buildings and scenery (with cross-fade; `tools/gltf.py --lod 0` exports the coarse one). Destructibles change state, not detail. Particles have no LOD. Collision always goes down through `lods[0]`. The game's shadow uses a fixed LOD per blocker (1200²; the final boss 20000²).
  - **Low mode rule:** index 0, but only where the automatic rule would draw some level (`d² < switchOutDis[0]`), otherwise level 0 shows up to the horizon; at the culling limit, apply the same alpha `t` as the automatic rule so it does not pop. The existing hook (`collect(ram, maxLod)`, used only by `viewer --lod n` and the L key) does not do this culling. For a "high" mode, use the highest index with `switchOutDis > 0`, not `numLods - 1` (Togera's costume 3 has a last level with 0, a mesh in A-pose).
  - **Main risk (check first):** the game only builds the VU1 packet of the level it chose; if the bone palette block (`animPktPtr[OBJECT + 0x68]`) of a level not chosen is not updated in the frame, skinning comes out with stale matrices. Check with an enemy near and far and `WOTM_LISTSKIN=1`; if it fails, build the palette from the skeleton (like `wotm_model.hpp`) or copy the one of the drawn level. Regression tests: the Dragon (two skinned objects in the same level) and CAPITOL (palette of 32 matrices).
  - **Care:** the mode applies only to the live collections (`wotm_live.inc`); `collectNative` of the VU1 check and the corpus replay stay on automatic, otherwise they flag a difference on every far object. Emitters and lens flare lights inside a level change along with it. Before looking for other cases like Togera costume 3, an inventory with `tools/ngp.py` (levels, `switchOutDis`, null `child`) per `.NGP` of MON and LVL.
  - Full study: `74221f4:docs/investigacoes/2026-10-23/lod_fixo.md`.

- **"Build your own city":** the game has no editor; the stage is `LVL/<fase>.NGP` (hier with the interactives, `dbInitDb`/ `dbProcInteractive`; `docs/FORMATOS.md`), with collision, AI paths (`PathNode`) and destructible buildings. First step: a mod that moves, removes or duplicates buildings of an existing stage; a visual editor (with the F5 free camera) comes later.
